## Repository configuration

- Primary origin: `https://ylei.de`, configured in `astro.config.mjs`. No repository-name base path.
- Canonical, Open Graph and Person structured URLs: generated by the shared layout from Astro's site origin.
- Search discovery: `public/robots.txt` references `https://ylei.de/sitemap-index.xml`; Astro emits sitemap locations at the primary origin.
- Domain artifact: `public/CNAME` contains only `ylei.de` and is copied into `dist/CNAME`.
- Validation: `npm run verify:build` audits all generated HTML, sitemap locations, robots and CNAME; GitHub Actions runs this after the production build. Browser verification checks the new canonical/OG/identity origin and served robots/sitemaps. CNAME is checked in the artifact because Astro preview handles extensionless paths as page routes under `trailingSlash: always`.
- Documentation: README, AGENTS and the content guide use the new primary origin. GitHub repository identifiers and the GitHub Pages DNS target keep their existing names.

According to [GitHub's official documentation](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site), an Actions deployment uses the Pages custom-domain setting; it does not depend on a CNAME file to configure that setting. The checked-in artifact records intent and prevents source/build drift. GitHub handles default-host and `www` redirects when the domain settings and DNS are configured.
